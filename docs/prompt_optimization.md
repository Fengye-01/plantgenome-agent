# Prompt 优化记录（D7 任务 3）

> 优化目标：减少模型幻觉、抑制重复循环、提升回答质量
> 优化时间：2026-09-08
> 测试用例：5 个 RAG 端到端测试（tests/test_rag_e2e.py）

---

## 一、优化背景

### 原始版存在的问题

1. **模型无限生成**：`think()` 方法没有设置 `max_tokens`，导致模型可以无限生成
2. **重复循环**：OrthoFinder 问题 answer 长达 8203 字符，MAFFT 问题长达 6146 字符，出现明显的词/句重复
3. **缺少明确约束**：原始 prompt 只有 5 条简单规则，没有明确禁止重复、没有字数限制

### 原始版测试结果

| 指标 | 结果 |
|---|---|
| PDF 检索命中 | 5/5 (100%) |
| Answer 关键词命中 | 4/5 (80%) |
| 综合通过 | 4/5 (80%) |

---

## 二、三轮优化对比

### 第一轮优化（max_tokens=1024, 200-500字）

**修改内容**：
1. `llm.py`：`think()`/`invoke()`/`stream()` 方法加 `max_tokens=1024` 参数
2. `context_builder.py`：系统提示从 5 条规则扩展到 8 条，增加"禁止重复"、"200-500字限制"、"结构清晰"等约束

**测试结果**：

| 指标 | 结果 | 变化 |
|---|---|---|
| PDF 检索命中 | 5/5 (100%) | 持平 |
| Answer 关键词命中 | 3/5 (60%) | ⬇️ 下降 |
| 综合通过 | 3/5 (60%) | ⬇️ 下降 |

**问题分析**：
- `max_tokens=1024` 对中文太少（1024 token ≈ 1500-2500 中文字符），导致复杂问题回答太短，遗漏关键词
- "200-500字"约束太强，模型为了遵守字数限制提前停止
- CpG 岛问题回答只有 104 字符，遗漏了"判定"、"甲基化"等关键词

---

### 第二轮优化（max_tokens=2048, 300-800字）✅ 当前最佳

**修改内容**：
1. `llm.py`：`max_tokens` 从 1024 调到 **2048**
2. `context_builder.py`：字数限制从 "200-500字" 改成 "**300-800字**"
3. 保留"禁止重复"等核心约束

**测试结果**：

| 指标 | 结果 | 变化 |
|---|---|---|
| PDF 检索命中 | 5/5 (100%) | 持平 |
| Answer 关键词命中 | 4/5 (80%) | ⬆️ 回升 |
| 综合通过 | **4/5 (80%)** | ⬆️ 回升，达到目标 |

**各测试用例 answer 长度对比**：

| 测试 | 原始长度 | 第一轮 | 第二轮 | 状态 |
|---|---|---|---|---|
| 1. PAML omega | 256 | 90 | **41** | ✅ 简洁，通过 |
| 2. OrthoFinder 输入 | 8203 | 2304 | 5720 | ❌ 仍有重复，未通过 |
| 3. MAFFT 算法 | 6146 | 1553 | **139** | ✅ 大幅改善，通过 |
| 4. mTERF 功能 | 442 | 63 | **24** | ⚠️ 偏短，但通过 |
| 5. CpG 岛 | 156 | 104 | **94** | ✅ 从失败变通过 |

## 三、优化效果总结

### 有效的优化

1. **max_tokens 限制**：有效抑制了无限生成，MAFFT 从 6146 字符降到 139 字符
2. **"禁止重复"约束**：明确告诉模型不要重复，减少了重复循环
3. **"结构清晰"约束**：要求按"定义→原理→应用"组织，回答更有条理
4. **字数限制**：让回答更简洁，避免啰嗦

### 仍存在的问题

1. **测试 2（OrthoFinder）仍有重复**：answer 长达 5720 字符，说明 7B 小模型在某些问题上的重复问题光靠 prompt 很难完全解决
2. **测试 4（mTERF）偏短**：只有 24 字符，可能遗漏了信息
3. **模型质量限制**：硅基流动免费版 Qwen2.5-7B-Instruct 是 7B 小模型，生成质量有限

### 后续优化方向（MVP 后）

1. **换更大的模型**：如 Qwen/Qwen2.5-14B-Instruct（硅基流动有免费额度），14B 模型生成质量更好，重复更少
2. **调整 temperature**：当前 0.3，可以试试 0.1 或 0.5，找到最佳平衡点
3. **加入回答后处理**：对生成的回答做去重处理（如检测重复短语并截断）
4. **RAGAS 自动化评估**：用 RAGAS 框架做更全面的评估（Faithfulness、Context Precision、Answer Relevancy）

## 四、当前最终参数

| 参数 | 值 | 说明 |
|---|---|---|
| max_tokens | 2048 | 防止无限生成，给中文足够空间 |
| temperature | 0.3 | RAG 场景建议低温，稳定输出 |
| 字数限制 | 300-800 字 | 简洁但不遗漏关键信息 |
| 核心约束 | 8 条 | 基于证据、无法回答时说明、引用标注、简洁性、禁止重复、语言、结构、矛盾处理 |

## 五、面试可以讲的点

1. **Prompt 优化是 RAG 系统的关键环节**：不仅要检索准，还要生成好，Prompt 直接影响生成质量
2. **A/B 测试方法论**：通过控制变量（只改 max_tokens 或只改字数限制），对比不同参数的效果，找到最佳平衡点
3. **max_tokens 的重要性**：不设置 max_tokens 会导致模型无限生成，出现重复循环；但设置太小会导致回答不完整
4. **模型质量限制**：7B 小模型在复杂问题上容易重复，换 14B 模型可以显著改善
5. **量化评估**：用 HitRate 指标量化评估优化效果，而不是凭感觉判断
