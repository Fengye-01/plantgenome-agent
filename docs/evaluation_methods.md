## 一、RAG 评估核心指标

### 1. Faithfulness（忠实度）
- **定义**：答案是否完全基于检索到的上下文，有没有编造上下文里没有的信息
- **为什么重要**：直接衡量幻觉程度，是 RAG 系统最重要的指标
- **计算方式**：用 LLM 作为评判器，把答案拆成多个陈述，逐个判断是否能在上下文中找到依据
- **公式**：Faithfulness = 有依据的陈述数 / 总陈述数
- **目标**：越高越好，理想值 1.0

### 2. Context Precision（上下文精确度）
- **定义**：检索到的内容里，真正有用的内容是否排在前面
- **为什么重要**：LLM 对排在前面的上下文更敏感，有用的内容排后面可能被忽略
- **计算方式**：用 LLM 判断每个检索到的 chunk 是否与问题相关，然后计算精确率
- **公式**：Context Precision = 相关 chunk 数 / 总检索 chunk 数（考虑排序权重）
- **目标**：越高越好，说明 Reranker 和检索策略有效

### 3. Context Recall（上下文召回率）
- **定义**：标准答案需要的信息，有多少被检索到了
- **为什么重要**：衡量检索是否漏掉了关键信息
- **计算方式**：用 LLM 判断标准答案的每个信息点是否在检索上下文中
- **公式**：Context Recall = 被检索到的信息点数 / 标准答案总信息点数
- **目标**：越高越好

### 4. Answer Relevancy（答案相关性）
- **定义**：回答是否切题，有没有答非所问
- **为什么重要**：即使检索正确，LLM 也可能生成不相关的回答
- **计算方式**：用 LLM 判断答案是否直接回答了问题，有没有冗余信息
- **目标**：越高越好

### 5. Context Entity Recall（上下文实体召回率）
- **定义**：标准答案中的关键实体（基因名、蛋白名、方法名等），有多少被检索到了
- **为什么重要**：生物信息学领域实体很多，实体召回率直接影响答案准确性
- **适用场景**：专业领域 RAG

## 二、Agent 评估指标

### 1. 工具调用准确率
- **定义**：Agent 是否选择了正确的工具
- **计算方式**：人工标注每个问题应该调用的工具，对比 Agent 实际调用的工具
- **我们的项目**：Router 分类准确率 = 9/10 = 90%

### 2. 任务完成率
- **定义**：Agent 是否成功完成了用户的任务（不只是调用了工具，还要返回正确结果）
- **计算方式**：人工判断 Agent 的最终回答是否满足用户需求
- **我们的项目**：5 类端到端测试 5/5 = 100%

### 3. 平均工具调用次数
- **定义**：完成一个任务平均需要调用几次工具
- **意义**：次数少说明效率高，次数多可能是 Agent 不够智能或工具设计不合理
- **我们的项目**：当前是单工具调用，平均 1 次

### 4. 端到端响应时间
- **定义**：从用户输入到返回最终回答的总时间
- **意义**：用户体验指标
- **我们的项目**：文献检索类平均 ~12s，纯计算工具 <0.1s

## 三、评估集构建方法

### 1. 黄金测试集（Golden Dataset）
- **定义**：人工标注的测试集，每个问题包含：问题、标准答案、参考上下文
- **构建步骤**：
  1. 从知识库中随机抽取文档片段
  2. 基于文档片段生成问题（可以用 LLM 辅助生成，人工审核）
  3. 人工标注标准答案
  4. 标注参考上下文（哪些文档片段包含答案）
- **我们的项目**：D4 已构建 15 题检索测试集，D17 计划扩展到 20 题

### 2. 测试集多样性
- **问题类型**：事实型、概念型、比较型、流程型、边界型
- **难度分布**：简单（直接在文档中找答案）、中等（需要跨文档整合）、困难（需要推理）
- **覆盖范围**：覆盖知识库的主要主题（PAML、OrthoFinder、MAFFT、mTERF、CpG 岛等）

### 3. 自动化评估 vs 人工评估
| 评估方式 | 优点 | 缺点 | 适用场景 |
|---------|------|------|---------|
| 自动化（RAGAS） | 可重复、成本低、可大规模 | 需要 LLM 作为评判器、有误差 | 回归测试、A/B 对比 |
| 人工评估 | 准确、能判断语义 | 成本高、不可重复、有主观偏差 | 最终验收、复杂问题 |
| 混合评估 | 自动化初筛 + 人工抽检 | 平衡成本和准确性 | 生产环境 |

## 四、RAGAS 框架简介

### 1. 什么是 RAGAS
- **RAGAS**（RAG Assessment）是一个开源的 RAG 评估框架
- 用 LLM 作为评判器，自动化计算 Faithfulness、Context Precision、Answer Relevancy 等指标
- 支持 Python，集成 LangChain

### 2. RAGAS 核心指标实现
- **Faithfulness**：LLM 把答案拆成陈述，逐个判断是否有上下文依据
- **Context Precision**：LLM 判断每个 chunk 是否相关，计算精确率
- **Answer Relevancy**：LLM 判断答案是否切题，生成潜在问题并对比

### 3. 我们的项目什么时候引入 RAGAS
- **MVP 阶段（当前）**：用简单的 HitRate@3 + 人工判断，快速验证
- **V2 阶段（D17+）**：引入 RAGAS，构建 20 题评估测试集，自动化计算 Faithfulness、Context Precision、Answer Relevancy
- **为什么不现在引入**：RAGAS 需要 LLM 作为评判器，每次评估都要调用多次 LLM，成本高、速度慢；MVP 阶段先把功能做稳定，评估可以后续完善

> "我在 MVP 阶段用了简单的 HitRate@3 作为检索评估指标，在自建的 15 题测试集上达到了 93.3%。同时我也做了 Router 分类准确率（90%）和 Agent 端到端通过率（100%）的评估。HitRate@3 的局限是只衡量检索是否命中，不衡量回答质量，所以 V2 我计划引入 RAGAS 框架，计算 Faithfulness（忠实度）、Context Precision（上下文精确度）和 Answer Relevancy（答案相关性），做更全面的评估。"
